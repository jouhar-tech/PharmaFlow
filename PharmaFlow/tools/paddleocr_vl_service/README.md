# PharmaFlow PaddleOCR-VL 1.5 local invoice service

This service runs PaddleOCR-VL-1.5 locally and exposes one private HTTP API for PharmaFlow.

The ASP.NET application calls PaddleOCR first. If the local service is unavailable, times out, returns an extraction error, or produces no usable invoice rows, PharmaFlow automatically falls back to the existing Gemini invoice service.

## API

Health check:

`GET http://127.0.0.1:8119/health`

Invoice extraction:

`POST http://127.0.0.1:8119/extract`

The endpoint accepts a multipart field named `invoice` and returns Markdown generated by the complete PaddleOCR-VL document parsing pipeline.

## Windows setup

Use Python 3.9-3.13.

Create a virtual environment:

`python -m venv .venv`

Activate it:

`..venv\Scripts\activate`

Install dependencies:

`python -m pip install --upgrade pip`

`python -m pip install -r requirements.txt`

Start the service:

`python -m uvicorn app:app --host 127.0.0.1 --port 8119`

The first startup/inference may download model files and take longer.

## Optional API key

For a private local deployment, set:

`set PADDLEOCR_API_KEY=your-local-secret`

Then set the same value in PharmaFlow configuration under `PaddleOCR:ApiKey`.

## Hardware

The direct PaddlePaddle pipeline supports x64 CPU and several GPU paths. CPU inference may be significantly slower than GPU inference, but it has no per-request provider quota because the model runs locally.

## Environment variables

- `PADDLEOCR_DEVICE`: default `cpu`
- `PADDLEOCR_PIPELINE_VERSION`: default `v1.5`
- `PADDLEOCR_API_KEY`: optional shared local-service secret

PaddleOCR-VL is used as a complete document parsing pipeline with layout detection and VLM recognition. PharmaFlow enables document orientation classification and document unwarping because pharmacy invoices are commonly photographed at an angle.
